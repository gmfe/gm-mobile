# 修改后验证

> 按需加载:第二阶段修改完成后必须执行。只使用 Claude Code 原生工具完成。

## 原生验证(必须执行)

subagent 参与修改时,主流程必须检查实际文件和最终 diff,不能仅依据 subagent 的完成摘要:

- [ ] 用 Grep 重新搜索确认范围内的中文候选,再用 Read 逐项确认剩余内容是已包裹、合法跳过还是遗漏
- [ ] 用 Grep/Read 检查没有重复包裹、反引号形式的 `t()`、碎片化动态翻译或错误调用目标
- [ ] 用 Read 检查 `src/locales/zh.json` 的 JSON 结构、逗号、引号和新增 key 位置
- [ ] 对每个动态调用逐项比对源码参数和 locale `${VARn}`,确保集合及顺序一致
- [ ] 用 Read 检查修改文件的 `gm-i18n` import,没有缺失或重复 named import
- [ ] 检查最终 diff 只包含用户确认的源码、import 和 locale 修改

## 可选本地校验

只有项目已经提供对应依赖和命令时,才可额外执行:

- 对已修改文件运行项目本地 Prettier
- 对已修改源码运行项目本地 ESLint
- 运行 `git diff --check`
- 使用项目现有 Node 运行时执行 `JSON.parse` 校验

不得为运行校验安装依赖、插件或 CLI。可选校验不可用时,原生验证仍必须完成,并如实报告未执行项。

## 最终报告格式

```md
## i18n 包裹报告

- 确认并处理:X 处
- 静态中文包裹:X 处
- 动态 key:新增 X 个,复用 X 个
- 修改 import:X 个文件
- 跳过:X 处
- 冲突/失败:X 处
- 复扫残留:X 处(附原因)
- 原生验证:结果
- 可选本地校验:已执行项及结果 / 未执行原因
```
