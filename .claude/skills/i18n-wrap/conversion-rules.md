# 转换规则参考

> 按需加载:实际执行包裹转换时阅读。调用风格与 import 策略遵循 SKILL.md §7。

以下示例使用项目默认的 `t()`。若文件已有 `i18next.t()` 风格,则等价替换为 `i18next.t()`,不要为统一风格改写存量调用。

## JSX 文本

```jsx
// before
<Button>保存</Button>
// after
<Button>{t('保存')}</Button>
```

若 JSX 文本与表达式共同组成一个自然句,优先按动态完整句处理(见下文「动态模板字符串」)。若跨嵌套标签且无法在不改变 DOM 或样式的情况下整体提取,列入「需人工判断」,禁止机械地逐片包裹。

## JSX 属性

只处理确认面向用户的属性:

```jsx
// before
<Input placeholder='请输入商品' />
// after
<Input placeholder={t('请输入商品')} />
```

自定义组件属性必须结合组件语义判断,不能认为所有字符串属性都需要翻译。

## 普通字符串

只有确认字符串进入用户界面时才包裹:

```js
// before
Tip.success('保存成功')
// after
Tip.success(t('保存成功'))
```

对象和数组中的字符串需要追踪消费端;禁止「一律包裹所有字符串值」。

## 无插值模板字符串

```js
// before
Tip.info(`暂无可处理订单`)
// after
Tip.info(t('暂无可处理订单'))
```

禁止生成反引号形式的 ``t(`暂无可处理订单`)``,统一改为单引号静态 key。

## 动态模板字符串与字符串拼接

```js
// before
`搜索的商品【${searchText}】不存在，是否追加？`
// after
t('APPEND_MISSING_SKU_CONFIRM', {
  VAR1: searchText,
})
```

```json
{
  "APPEND_MISSING_SKU_CONFIRM": "搜索的商品【${VAR1}】不存在，是否追加？"
}
```

规则:

- key 使用稳定、可读、与业务语义对应的大写蛇形命名;禁止 `KEY1`、`KEY2` 等无语义 key
- 动态表达式按出现顺序映射为 `VAR1`、`VAR2`;参数值可以是属性访问或表达式,例如 `VAR1: sku.name`
- 不得改变表达式求值顺序
- 动态表达式包含中文分支或复杂控制逻辑时,拆成完整句子的不同 key,或列入人工判断

字符串加法组成的动态完整句与模板字符串使用相同规则。
